## 失败、修复和复验

1. 原路径 `docs/planning` 不存在，实际为 `doc/planning`；读取后统一目录，未丢弃计划。复制验证源文件时 Git 默认转义中文文件名，改为 `git -c core.quotepath=false ls-files` 后完整复制三份计划。
2. 沙箱的 npm 请求访问本机代理时出现 EACCES；通过工具允许的联网执行完成官方注册表核实与安装。没有改用未知镜像。
3. pnpm 11 不读取 `.npmrc` 中普通设置；移至 `pnpm-workspace.yaml` 并查询生效值。第一次安装又因未决的 `@parcel/watcher` / `unrs-resolver` 安装脚本策略失败；显式关闭当前不需要的源码构建脚本后冻结安装通过，当前平台预构建依赖满足测试。
4. 首次 lint 把 CJS 测试当作其他 sourceType，报 require/module 未定义；明确 `sourceType: commonjs` 后通过，没有关闭 no-undef。
5. 沙箱内 API 启动成功，但回环 HTTP 验证失败（13/14 通过）。在允许本地网络的执行环境下，同一应用与测试通过 14/14；不把受限环境结果伪报为通过。
6. 验证副本触发 Jest workspace 名称碰撞；把 Jest roots 限制为 tests。随后隐藏目录路径中的 `<rootDir>` glob 在 Windows 下导致“找不到测试”；改为 roots 限定范围内的 `**/*.test.cjs`，干净副本完整复验通过。
